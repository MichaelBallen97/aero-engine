# Task 2.5.1 — save/load/new from editor

**Deliverable:** the four File-menu items — New Scene, Open Scene…, Save Scene, Save Scene As… — all
live, each driven by SDL3's **native** file dialogs where one is needed; a `SceneSession` holding the
current scene's absolute path; the dirty flag read straight from `CommandStack::isClean()` (the seam
2.4.1 built for this task); an unsaved-changes confirmation modal that guards **New, Open *and* quit**

data-corruption invariant, not a cosmetic one. The whole file-flow state machine (menu → guard → modal

(`scene_session.cpp`), which is what makes almost the entire transition table tier-0 testable with no
window and no GPU.

## The 2026-07-31 code-review round

Unlike 2.4.2, this task's implementation pass claimed no code-review round was needed — that claim
was **wrong**. A review found **nine findings, two blocking**, all fixed on the same branch with no
rebase/amend, following the same seed-back discipline as every sabotage row above.

**BLOCKING 1 — `flow.requestedPath` was bound to the wrong operation and leaked.** The
`AskWhereToSave` arm of the modal resolution (reached when the modal's "Save" answer needs a target
because the document is untitled) used to consume `flow.requestedPath` unconditionally — but that
field can just as easily hold the target of a **pending, still-deferred Open** (`requestOpenScene(path)`
sets both `flow.requested`/`flow.requestedPath` together, and the guard leaves `requestedPath` alive
across the modal so the Open can still be performed once the way is clear). Concrete data loss: dirty +
untitled document, `requestOpenScene("/tmp/level1.scene.json")` → guard raises `Confirm` → user answers
**Save** on the modal → the old code wrote the **current** scene over `/tmp/level1.scene.json`, then
tried to open the file it had just destroyed. A second half: no abandon path (Cancel, the dialog-in-flight
swallow, `applyDialogResult`'s failed/cancelled returns) ever cleared the field, so a stale value could
also hijack a **later, unrelated** `Save As` with no dialog and no overwrite prompt.
**Fix:** the `AskWhereToSave` arms (both the modal-triggered one and the un-guarded `SaveScene`'s own)
no longer read `flow.requestedPath` as a save target at all — no hook in this tree ever populates it for
that purpose, only `requestOpenScene(path)`/`requestSaveSceneAs(path)` do, for different actions each —
and `flow.requestedPath.clear()` was added to every path that abandons or defers the pending action:
Cancel, the `WriteNow` write-failure branch (found during the fix, same root cause, not in the original
report), the `AskWhereToSave` no-channel abandon, the dialog/modal swallow, and both of
`applyDialogResult`'s early returns. New tests: **SS31** (guarded Open + modal Save on an untitled
document must not write to the Open target — byte-identical file content, `session.untitled()` stays
true), **SS32** (a cancelled guarded Open clears `requestedPath`, so it cannot hijack a later Save As),
**SS33** (the same leak at the `WriteNow` arm — a titled document whose Save write fails must abandon
the Open's own target too). **Seed-back verdict:** reintroducing the exact original `AskWhereToSave`
branch (the `!flow.requestedPath.empty()` direct-write arm) reddens **SS31 alone**, exactly as
predicted — proved present with `git diff` first, whole 296-entry suite measured, reverted, build
re-confirmed green.

**BLOCKING 2 — nothing gated a File request on `flow.confirmOpen`.** `shell_ui.cpp`'s `fileEnabled` and
`scene_session.cpp`'s swallow guard both tested only `flow.dialog`. The unsaved-changes modal itself
being up did not stop a chord (or a raw `request*()` call) from reaching `AskWhereToSave` and launching
a **second**, native Save dialog on top of the still-open ImGui modal — verified against the vendored
ImGui 1.92.8 source: `CalcRoutingScore` (`imgui.cpp:10326`) grants `ImGuiInputFlags_RouteGlobal` with no
modal test at all. **Fix:** `applyFileRequests`'s dialog-in-flight swallow (`scene_session.cpp`) now also
fires on `flow.confirmOpen`, and `shell_ui.cpp`'s `fileEnabled` now reads
`flow.dialog == DialogKind::None && !flow.confirmOpen`, mirroring the state-machine change at the UI
layer as defence in depth. New test: **SS27b** — with the modal up (`confirmOpen == true`, `dialog ==
None`) and an unrelated pending action already queued, each of the five requests in turn is a no-op:
nothing launches, the original pending action survives untouched. **Seed-back verdict:** dropping the
`|| flow.confirmOpen` disjunct reddens **SS27b alone** (4 assertion failures within that one case),
exactly as predicted — proved present with `git diff` first, whole suite measured, reverted, build
re-confirmed green.

## Known-and-expected, NOT a defect

- **Closing a clean editor now draws one more frame before exiting.** The window `[X]` used to set
  `running = false` before any ImGui call; it now routes through the guard, which decides inside the
  frame. Deliberate (D1/AC-28) and the reason the ImGui frame stays balanced.
- **A read-only scene file is silently replaced on macOS and Linux, and reports an OS error on
  Windows** (plan A7). POSIX `rename` does not consult the target's mode. The user chose the file in a
  native panel that already asked about overwriting.
- **`Ctrl+O` is not `Cmd+O`-on-Windows and vice versa** — `ImGuiMod_Ctrl` maps to Cmd on macOS
  automatically. There is no `#if defined(__APPLE__)` anywhere and there must not be.
- **The editor camera does not move on New or Open** (D22). Viewport state is not document state.
- **A freshly opened scene's Hierarchy order is file order**, and it settles on the frame after the
  load (`RootOrder::reconcile` runs in the Hierarchy's phase 1). One frame, not a bug (E6).

## How to validate one OS

1. **New Scene** on a fresh editor: three entities appear (Main Camera, Directional Light, Cube), the
   title reads `Untitled - Aero Editor`, Edit > Undo is greyed out.
2. Move the Cube with the gizmo: the title gains a leading `*`. **Undo it: the `*` disappears** (D3 —
   dirtiness is history arithmetic, not a one-way latch).
3. ⚠ **Save Scene As…** with a `*` showing: the native Save panel opens, **parented to the editor
   window** (it is a sheet on macOS), pre-filled `Untitled.scene.json`. Save it; the title becomes
   `*`-free and reads the file name.
4. Edit something, **`Ctrl+S`**: no dialog, the file updates on disk, the `*` clears. Then check
   File > Save Scene is **greyed** (clean **and** titled — AC-4) and Save Scene As… is not.
5. ⚠ **Open Scene…**: the native Open panel **starts in the saved scene's folder**, filters to `.json`,
   and opening the file restores exactly what was saved.
6. ⚠ **Hold `Ctrl+S` for two seconds** (S17/AC-3): the file is written **once**, not sixty times — watch
   the Log panel, which must not flood, and the file's modification time, which must move once.
7. **New Scene** with unsaved changes: the modal appears asking about **the right document name**.
   Press **Cancel**: nothing changes at all — same entities, same selection, same undo history, same
   `*`.
8. Repeat, press **Don't Save**: the default scene replaces it immediately.
9. Repeat, press **Save** on a *titled* scene: it writes and *then* does the New.
10. ⚠ **The chain (D11/S23).** With an untitled dirty scene, File > Open → the modal → **Save** → the
    native Save panel opens → press **Cancel** in the *native* panel. The Open is **abandoned**: the
    original scene is still there, still dirty. Nothing was opened and nothing was lost.
11. **The quit guard (D1).** With unsaved changes, click the window's **close button**: the modal
    appears and the editor **does not close**. Cancel; the editor is still running and unchanged.
12. Repeat with **`Ctrl+Q`** and with **File > Exit** — identical behaviour from all three.
13. Quit with a **clean** document: it closes immediately, no prompt. *(Expect exactly one extra frame
    before the window disappears — see "Known-and-expected".)*
14. ⚠ **Esc on the modal (AC-27).** It dismisses as Cancel and the editor **does not quit**. **This row
    is the only proof of AC-27 anywhere in this tree** — if the modal ignores Esc, the hand-bound key
    regressed and no test will tell you.
15. **The INV-6 trap (S1/D2).** Move the Cube, delete it, **New Scene** (Don't Save), then press `⌘Z`
    twice. **Nothing happens** — no ghost Cube from the previous scene appears in the new one. This is
    the row the whole of D2 exists for.
16. **Malformed file (AC-11).** Corrupt a saved scene in a text editor (delete a `}`), Open it: an ERROR
    appears in the Log panel **with a line and column**, and the scene on screen is **untouched** —
    entities, selection **and undo history** all still there. Press `⌘Z`: it undoes the edit it always
    would have.
17. ⚠ **Atomic write (S6/AC-19).** Save a large scene, then force-quit the editor during the save if you
    can catch it; the previous file is intact and **no `.aero-tmp` remains beside it**.
18. Open a scene, edit it, Open a **different** scene without saving: the modal guards it.
19. ⚠ The four File items are **greyed out** while a native dialog is open (D8/AC-5) — leave the panel
    up and open the File menu.
20. ⚠ **Linux only.** On a box with neither XDG portals nor zenity, Open Scene… logs **exactly one**
    ERROR and the editor keeps running normally (F4/S14).
21. `⌘Z` still works, the Hierarchy's rename field still swallows it while focused, and the gizmo,
    picking and the Inspector are all unaffected (the standing regression row — and E5's only check
    that a panel's cached `Entity` survives a swap).
22. Re-run **2.2.5's four BLOCKED rows** against this task's log records (D21) — an INFO on every
    successful load and a WARN on a skipped component are both **non-Debug-only** sources, unlike the
    three that existed before this task. *(2.4.2's row 22 carried this same clause and it was not
    performed; it is carried forward here deliberately, not duplicated by accident.)*

**Platform notes.** No row here is platform-exclusive except row 20 (Linux only). Rows 3, 5, 6, 10, 14,
17 and 19 require native OS dialogs/keyboard and cannot be performed over a remote desktop with input
smoothing.

**The priority rows, if time is short:** **15** (the INV-6 trap — the whole reason this task touches
`CommandStack`/`World` ownership), **14** (Esc on the modal — the only proof of AC-27 anywhere), **10**
(the full Save-As-then-Cancel chain — D11's worst-case scenario), **11/12** (the quit guard from all
three paths).
