**Deliverable:** a reflected `SetFieldCommand` covering every component field (the Inspector's seven
`writeComponentField` arms), `AddComponentCommand`/`RemoveComponentCommand` wrapping 2.2.2's

returns), `⌘Z` again — **the move undoes too**, because the returning entity is the *same* handle, not a

#### The nine findings

1. **S2a — the F5 occupied-index pre-check is not independently tested.** Dropping it alone leaves the
   suite at 94/94; W3's occupied-index arm only reddens once the trailing `made != entity` belt is
   *also* removed (S2b). What the suite proves is the belt's **outcome**, not the pre-check's existence.
   §V4 predicted this branch and called it a finding rather than a pass; it is confirmed.
2. **S6 — phase A's rollback was entirely untested. This was a real gap, found by the matrix, not by
   review, and it is now closed.** N7 pre-occupies the **first** record's index, so phase A refuses on
   record 0, `created == 0`, and the rollback loop iterates zero times — deleting the loop outright
   changed nothing. Proven, not inferred: replacing the loop body with `world.clear()` when
   `created > 0` (a probe that would wipe the World if the body were ever entered) also left the suite
   at **94/94**, so it is never reached with `created > 0` anywhere in the inventory. **`N13`** was added
   to `scene_snapshot_test.cpp` to close it: two independent roots, `b` destroyed last so entt's LIFO
   free list hands its index back first, occupying **only** `b`'s slot — phase A must recreate `a`,
   refuse `b`, destroy `a` again and return `false`. Re-seeding S6 with N13 present reddens **N13 and
   nothing else**, on `CHECK_FALSE(world.alive(a))` and `world.entityCount() == 1`.
3. **S9/S10 — the Inspector's gate pair has no mechanical proof of any kind.** Both edges were seeded
   (S9 into five arms, S10 into all seven) and both left the suite at 94/94, P8 included; the §V7
   `breakMergeChain` grep also stays at 14 under S10. `InspectorPanel` is src-private and ImGui-bound,
   so no target can construct it, and P8 pins the *policy* against a bare `CommandStack`. **Human rows 3
   and 6 are the only proof of AC-25's second half that exists.**
4. **S4 — the dangling `string_view` is NOT sanitizer-visible, and §V4's claim that it would be is
   inverted here.** The plan said "ASan aborts N1/N10 — an abort, not a red assertion… a *stronger*
   result than a failed `CHECK`". Measured on the macOS Debug preset with ASan **and** UBSan confirmed
   on (`AERO_ENABLE_SANITIZERS:BOOL=ON`, `-fsanitize=address,undefined -fno-sanitize-recover=all`):
   **zero sanitizer output**, and five ordinary red `CHECK`s. The reason is that the World's name
   records live in an EnTT swap-and-pop pool — destroying the entity leaves the freed record's bytes
   inside a still-mapped, still-live pool page, overwritten by the swap, which ASan cannot flag.
   **Standing lesson: a dangling view into a pooled component must never be assumed sanitizer-visible.**
   The ordinary assertions are what catch it.
5. **S12 — X1 is not a discriminator and structurally cannot be.** X1 only pushes a
   `CreateEntityCommand` and asserts the selection *after the push*; it never calls `undo`. The cases
   that actually fire are **X2, X3, X7, X8** (X7 being the other name §V4 gives, correctly).
6. **S13 — two of three named discriminators do not fire.** Only **R3** reddens. **X7 does not** (it
   inserts at slot 1 into a list of size 2 — in range, so the clamp direction is irrelevant) and **I8
   does not** (slot 2 into a list of size 2 — `min(2,2) == 2` either way). No command-level or
   real-frame test exercises an out-of-range slot; the clamp direction rests on R3 alone.
7. **S15 — X12 does not fire.** X10 does, as predicted. X12 restores `a1` to slot 1 of a 2-child parent
   and `b0` to slot 0 of a 1-child parent — both coincide with a plain append, so the position restore
   is invisible there. X12 must not be counted as sibling-slot coverage.
8. **S16 — one row, two commands, two seeds.** Seeding only `CreateEntityCommand::redo` (what the row's
   text says) reddens **X3 and X18** but **not X9**; X9 is only reachable by separately seeding
   `DuplicateEntitiesCommand::redo`. Both were run. The §V4 row should be split.
9. **S18 — I9, the named discriminator, is vacuous against this defect class.** With every panel handed
   a decoy `RootOrder`, I9's `CHECK(&cmd.roots == firstTick)` stays green, because I9 builds its own
   `CommandContext` from `app->roots()` — still the "real" object. §V4 predicted the non-result and
   asked for it to be recorded rather than claimed as coverage. The measured addition: **S18 is caught
   anyway — by I8**, which fails hard because the panel reconciles the decoy and `app->roots()` stays
   empty. I9 must not be cited as the proof.

## Known-and-expected, NOT a defect

- **AC-10 (tag/empty component values round-tripping through structural undo) is an honest, currently
  unreachable gap, not a defect to be filed.** None of the five built-in components is an empty (tag)
  type, and `SubtreeSnapshot`'s private store World only ever runs `registerBuiltinComponents` — a
  test-defined tag is captured but can never be mirrored into that private store, so it always degrades
  to **absent** with exactly one WARN, never rounds trip. This becomes reachable the day project-defined
  components (Phase 4/5) register into the snapshot's private World too (handoff H3). Nothing in this
  tree claims tags round-trip; `N6`/`N11`/`X16(b)` assert the degrade, not the round trip.
- **E7** — `⌘Z` mid-Inspector-drag: the drag continues from the reverted value, no crash, no log flood.
- **E15** — history capacity bounds the memory a run of structural undos can hold; there is no separate
  per-command memory budget by design (D28).
- **E17** — a drag that returns to its own start value is still one undo entry, and undo of it is a
  visible no-op (`before == after`) — not a bug.
- `TransformCommand` stays gizmo-only, permanently (H5) — the Inspector's Transform fields route through
  `SetFieldCommand` like every other component, with zero special-casing.

## How to validate one OS

1. Type a new X into the Cube's `Transform.position`, press Enter: **Edit > Undo reads
   "Undo Transform.position"**. `⌘Z` restores the old value; `⇧⌘Z` reapplies it.
2. ⚠ **Drag** the position X field left and right for several seconds, release, `⌘Z` **once**: it returns
   to where it was **before the drag began** — one step, not one frame's worth.
3. ⚠ **Two separate drags on the same field → two undo steps.**
4. Drag position X, then drag position Y, then `⌘Z` twice: **Y first, then X**. They never collapse.
5. ⚠ Change a `bool`, a colour (`MeshRenderer.color`) and a **string** field: each is its own step, and
   the string field commits **once when it loses focus**, never per keystroke.
6. ⚠ **The ordering trap (S9/S10) — the only proof anywhere in this tree that the Inspector panel itself
   applies the D17 gate pair correctly.** Drag a field, release, `⌘Z`: the value returns to the pre-drag
   value in **one** press. **If it takes two, the close edge is on the wrong side of the push** — this is
   2.4.1's blocking Gap 1, reproduced in the Inspector. Seeding this defect directly left the whole
   mechanical suite (P8 included) green, so **this row is not backed up by any test tier** — treat a
   failure here as a real, uncaught regression.
7. Right-click a Hierarchy row → **Create Empty**, `⌘Z`: it disappears and the **previous selection comes
   back**. `⇧⌘Z`: it returns, **selected**.
8. ⚠ Select the Cube, **Delete**, `⌘Z`: it comes back **in the same row position**, with its name, its
   components and its values, and **it is selected again**. The headline row.
9. ⚠ Delete a **middle child** of a multi-child parent, `⌘Z`: it returns **between the same two
   siblings**, not at the bottom of the list.
10. ⚠ Delete the **first root**, `⌘Z`: it returns **at the top** of the Hierarchy, not under the last
    root.
11. ⚠ **The identity trap (S1/D2) — the canonical sequence from spec §0-D2, and the entire justification
    for touching the engine.** Move the Cube with the gizmo, **delete** it, `⌘Z` (it returns), `⌘Z`
    **again**: **the move is undone too**. If the second `⌘Z` does nothing (one WARN, step consumed),
    identity restoration is broken and `World::recreate` is not doing its job.
12. Multi-select three entities **including a parent and one of its own children**, Delete, `⌘Z`: all
    three subtrees return, **once each**, in their original positions.
13. `Ctrl/⌘+D` to duplicate, `⌘Z`, `⇧⌘Z`, `⌘Z`: the copies come and go cleanly **at every step**.
14. Drag a row onto another row (reparent), `⌘Z`: it returns to its **old parent at its old position**
    (check the *position*, not just the parent).
15. Drag a row to empty space (unparent to root), `⌘Z`: it returns **under its parent**.
16. `F2` rename, type, Enter, `⌘Z`: the old name is back. Then **rename to the same text**: **no new undo
    step appears in the Edit menu** (the Undo label is unchanged).
17. Inspector **+ Add Component** → pick one → `⌘Z`: it is gone. `⇧⌘Z`: it is back.
18. ⚠ Set **two non-default values** on a component, **Remove Component**, `⌘Z`: it returns **with both
    values**, not zeroed. S14 is silent data loss with a green mechanical suite; this is the human half
    of confirming it stays fixed.
19. **Known-and-expected.** `⌘Z` while *holding* an Inspector drag: the drag continues from the reverted
    value. **No crash, no console flood.**
20. **2.4.1 regression.** The rename field still swallows `⌘Z` while focused — the **text** undoes, the
    **scene does not move**.
21. **2.4.1 regression.** One gizmo drag is still exactly **one** undo step — this task must not have
    broken 2.4.1's own AC-16 fix.
22. In a **Debug** build the Console shows one `DEBUG editor: undo '<label>' (…)` per undo, now with
    **varied labels** ("Transform.position", "Delete Entity", "Rename", "Add MeshRenderer"…). In
    **Release** the same undo is silent (`NDEBUG` compiles the record out) — correct, not a defect.
    **⇒ Re-run 2.2.5's four BLOCKED rows here** (see `editor/VALIDATION.md`'s "what needs a human next").
23. Perform **130+ mixed edits** (drags, creates, deletes, renames), then **hold `⌘Z`** to the bottom: it
    stops cleanly at the capacity floor, nothing crashes, and the editor is still responsive. Watch RSS
